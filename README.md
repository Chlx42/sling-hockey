# 广告位招租 · Chlx 的弹射冰球

线上试玩：**http://123.56.69.142/hockey/**

2.5D 桌面弹射对战：按住自己半场的冰球拖到底线弹力带，后拉松手发射，穿过中央洞口送到对方半场，先清空自己半场的一方获胜。支持人机四档难度（轻松、标准、困难、极限）、在线匹配（无人时自动配 AI 陪练）和好友房间。

## 技术栈

- 前端：three.js + Rapier（WASM），原生 ESM 无打包器
- 物理：120Hz 固定步长，连续碰撞检测（CCD）、接触旋转、滑动/旋转阻力、静止休眠
- 后端：Node.js + Colyseus 0.18，权威服务器（出手校验、30Hz 调度推进 120Hz 物理、10Hz Schema 增量同步）
- 联机：原版 Colyseus SDK；浏览器本地模拟两次快照之间的碰撞与旋转，松手立即预测发射，服务器快照校正
- AI 陪练：真实 Colyseus 客户端，复用共享引擎并分片搜索，避免长时间阻塞房间更新
- 部署：systemd + nginx

## 运行

```bash
npm ci
npm start        # 服务端监听 127.0.0.1:3217
npm test         # 物理、预测与服务端回归
npm run smoke    # 需先启动本地服务，验证真实联机流程
node deploy/benchmark.mjs # 本机物理耗时，不包含渲染、AI与网络
node deploy/benchmark-network.mjs # 同轨迹下比较新旧 Schema 增量编码字节
```

`client/` 为纯静态文件，任意静态服务器托管即可；WebSocket 与 API 代理配置见 `deploy/nginx-sling-hockey.conf`。

生产环境通过 nginx 提供 `/hockey/` 静态页面、`/api/`、`/matchmake/`，以及
`/{processId}/{roomId}` WebSocket。服务端仅监听回环地址；修改反代时保留同站其他服务的路由。
排行榜目录由 `SLING_DATA_DIR` 指定，发布代码时保留该目录。

`client/js/game.mjs` 已包含运行所需客户端代码。重建需准备原始分析产物目录
（默认 `/tmp/bin-hlool-re`，可用 `SLING_BUNDLE_DIR` 指定），运行 `python3 deploy/build-game.py`；
构建会应用 `deploy/client-performance.patch`、`deploy/client-colyseus.patch`、
`deploy/client-physics.patch`、`deploy/client-island.patch`、`deploy/client-audio.patch`、
`deploy/client-clubhouse.patch`、`deploy/client-extreme.patch` 和 `deploy/client-quality.patch`，保留渲染优化、队列修复、本地预测、界面、音效、极限 AI 与高清设置。物理改动以 `engine/index.mjs`
为准，修改后重建客户端，发布时一起更新 `client/js/prediction.mjs`。

## 本地计算与服务器边界

单机对战的物理与 AI 都在浏览器运行，不创建服务端对局。联机时，浏览器使用与服务器
同源的 Rapier 引擎在本地预测；只上传抓取、瞄准、发射等操作，服务器仍校验操作并
决定胜负和排行榜。在线匹配的 AI 陪练仍运行在服务器上。

极限档采用 0.12° 瞄准误差、0.6% 力度误差、0.12–0.28 秒反应间隔和更短的拉带动作；
搜索比较多种力度并精调角度，仍走相同的抓球、弹力带和出手校验。极限搜索按实际计算时间
累计约 120ms 预算，每帧分片目标 5ms；完成当前候选可能略超预算。其余三档与在线普通陪练
保持原有策略。客户端控制器、难度说明和入口缓存版本通过极限补丁保留。

联机快照包含速度、角速度及弹射加速阶段；预测复用物理世界，最多外推 250ms，避免
断流后无限模拟。拒绝、重连、重开及结算会清理或校正预测状态；旧服务端缺少运动字段时
客户端回退到位置插值。10Hz 同步需要搭配新客户端发布，旧客户端仍能解码但表现会较滞后。
后台标签页暂停渲染与本地 AI，恢复后不补跑隐藏期间的积压帧。

快照时间使用已完成的物理子步时间，发送墙钟只参与时钟同步；发射不会重标其他球的时间。
客户端用模拟时钟推进，保留已开始的本地发射，收到确认时只登记权威结果。
抓取和放下立即更新本地碰撞体；输入序号与每方出手次数随棋盘快照确认，
同一物理时刻的消息也能按实际处理顺序接管预测。

碰撞声音与粒子直接由本地预测子步触发，不再等待 10Hz 服务端特效包。
快照回放按模拟时间水位和碰撞对象去重，超过 50ms 的旧反馈不补播；断流或后台恢复时
快照跳过的碰撞可能没有声音。启用本地反馈后，服务端不再向该客户端发送重复特效，
旧客户端仍保留原有兼容消息。粒子和冲击圈复用既有池，音效保持原有数量限制。

弹射最高速度由 37 调至 44，拉力指数由 1.15 调至 1.08；恒定滑动阻力由 4.5 调至 6，
让中等拉力更直接并缩短低速尾段。弹簧加速曲线、120Hz 步长和 AI 搜索预算保持一致，
力度显示与橡皮带反馈共用速度上限。碰撞音增加短促低频，缩短发射尾音和粒子寿命。

桌面音效在 `client/js/table-audio.mjs`：球、木框、中央挡板分别使用短促接触声与不同的
衰减共振，橡皮筋使用阻尼拨弦，拿放球也改为轻触桌面的声音。每类预生成四种细微变化，
按碰撞法向速度调整音量与亮度，并保留屏幕左右声像。碰撞按接触对象限频，避免不同球
同时撞墙时互相吞音；仍限制总声部数量，播放后释放音频节点，总线柔性限幅防止密集碰撞过载。
全部本地合成，无音频下载。
修改生成客户端中的音效接入时需同步 `deploy/client-audio.patch`；发布时一并更新音效模块。

静止时跳过物理求解，但比赛计时和胜负检测继续。降低同步/调度频率不降低物理精度，
也不代表服务器总 CPU 按相同比例下降；更长的滑行、旋转会增加活跃时间。实际容量还需
按真人/陪练比例和目标设备压测。

本机 120 秒模拟、交替 7 轮中位数：空闲物理耗时 119.23→10.42ms（约 -91%），
持续发射 143.27→148.85ms（约 +4%）；后者包含更持久的滑行旋转。这是此前物理版本的
测量，后续时间标记、输入确认与本次手感调整未重跑测试或基准。网络编码可用上述脚本自行测量，
它不包含首次握手、WebSocket 包头、碰撞事件或 AI；不能换算为总流量或线上容量。

## 小木桌主题

首页结构在 `client/js/island-ui.mjs`，主题样式在 `client/css/island.css`，本地 SVG 插画与图标在
`client/assets/`。页面和对局采用奶油纸卡、草地与浅木桌配色，无外部字体或图片依赖。
`deploy/client-island.patch` 保存生成客户端中的主题入口与渲染调整，构建脚本会在物理补丁后自动应用；
修改 `game.mjs` 的主题部分时需同步该补丁，避免重建丢失。

俱乐部改版通过 `deploy/client-clubhouse.patch` 在上述补丁之后应用。首页直接选择练习难度并开局，
在线匹配和好友对战独立呈现；玩法采用三步图解，详细规则按需展开。设置集中管理声音与辅助线，
好友页支持完整邀请链接、回车加入和输入错误反馈。切屏管理焦点，弹窗限制背景交互，
全局提示在菜单也可见；减少动态效果时，倒计时与状态仍以静态形式保留。
棋盘雾效移至远景，可抓球用细轮廓提示，手机视角下也能看清木框和棋子。
首页停止被遮挡的演示模拟与 WebGL 渲染。修改这轮 UI/交互或渲染时，同步俱乐部补丁；
发布需一起更新 `game.mjs`、`island-ui.mjs`、`island.css` 和 `index.html`。

设置中的“高清棋盘”默认开启，并记住 `sling.settings.highQuality`。开启时绘制分辨率上限为
2 倍、总像素预算 500 万，阴影为小屏 1536／大屏 2048；关闭后恢复较低的渲染开销。
切换即时生效，调整阴影大小时释放旧贴图。此开关通过 `deploy/client-quality.patch` 保留。
