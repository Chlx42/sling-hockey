# 广告位招租 · Chlx 的弹射冰球（sling-hockey）

线上试玩：**http://123.56.69.142/hockey/**

2.5D 桌面弹射对战：按住自己半场的冰球拖到底线弹力带，后拉松手发射，穿过中央洞口送到对方半场，先清空自己半场的一方获胜。支持人机三档难度、在线匹配（无人时自动配 AI 陪练）和好友房间。

常规时间 1 分钟，未清空半场则自动进入 2 分钟加时，隐藏双方辅助线并提示一次。全程清空己方半场即可获胜；加时结束时剩余棋子较少的一方获胜，相同则平局。常规时间的辅助线仍可在设置中开关。

## 技术栈

- 前端：three.js + Rapier（WASM），原生 ESM 无打包器
- 物理：120Hz 固定步长，连续碰撞检测（CCD）、接触旋转、滑动/旋转阻力、静止休眠
- 后端：Node.js + Colyseus 0.18，权威服务器（出手校验、30Hz 调度推进 120Hz 物理、10Hz Schema 增量同步）
- 联机：原版 Colyseus SDK；浏览器本地模拟两次快照之间的碰撞与旋转，松手立即预测发射，服务器快照校正
- AI 陪练：真实 Colyseus 客户端，复用共享引擎并分片搜索，避免长时间阻塞房间更新
- 部署：systemd + nginx

## 运行

```bash
npm ci
npm start        # 服务端监听 127.0.0.1:3217
npm test         # 物理、预测与服务端回归
npm run smoke    # 需先启动本地服务，验证真实联机流程
node deploy/benchmark.mjs # 本机物理耗时，不包含渲染、AI与网络
node deploy/benchmark-network.mjs # 同轨迹下比较新旧 Schema 增量编码字节
```

`client/` 为纯静态文件，任意静态服务器托管即可；WebSocket 与 API 代理配置见 `deploy/nginx-sling-hockey.conf`。

生产环境通过 nginx 提供 `/hockey/` 静态页面、`/api/`、`/matchmake/`，以及
`/{processId}/{roomId}` WebSocket。服务端仅监听回环地址；修改反代时保留同站其他服务的路由。
排行榜目录由 `SLING_DATA_DIR` 指定，发布代码时保留该目录。

`client/js/game.mjs` 已包含运行所需客户端代码。重建需准备原始分析产物目录
（默认 `/tmp/bin-hlool-re`，可用 `SLING_BUNDLE_DIR` 指定），运行 `python3 deploy/build-game.py`；
构建会应用 `deploy/client-performance.patch`、`deploy/client-colyseus.patch`、
`deploy/client-physics.patch` 和 `deploy/client-island.patch`，保留渲染优化、队列修复、本地预测与界面改版；`deploy/client-tabletop.patch` 保留材质音效、接触状态读取和高清棋盘。物理改动以 `engine/index.mjs`
为准，修改后重建客户端，发布时一起更新 `client/js/prediction.mjs`。

## 本地计算与服务器边界

单机对战的物理与 AI 都在浏览器运行，不创建服务端对局。联机时，浏览器使用与服务器
同源的 Rapier 引擎在本地预测；只上传抓取、瞄准、发射等操作，服务器仍校验操作并
决定胜负和排行榜。在线匹配的 AI 陪练仍运行在服务器上。

联机快照包含速度、角速度及弹射加速阶段；预测复用物理世界，最多外推 250ms，避免
断流后无限模拟。拒绝、重连、重开及结算会清理或校正预测状态；旧服务端缺少运动或带形变字段时
客户端回退到位置插值。10Hz 同步需要搭配新客户端发布，旧客户端仍能解码但表现会较滞后。
后台标签页暂停渲染与本地 AI，恢复后不补跑隐藏期间的积压帧。

快照时间使用已完成的物理子步时间，发送墙钟只参与时钟同步；发射不会重标其他球的时间。
客户端用模拟时钟推进，保留已开始的本地发射，收到确认时只登记权威结果。
抓取和放下立即更新本地碰撞体；输入序号与每方出手次数随棋盘快照确认，
同一物理时刻的消息也能按实际处理顺序接管预测。

碰撞声音与粒子直接由本地预测子步触发，不再等待 10Hz 服务端特效包。
快照回放按模拟时间水位和碰撞对象去重，超过 50ms 的旧反馈不补播；断流或后台恢复时
快照跳过的碰撞可能没有声音。启用本地反馈后，服务端不再向该客户端发送重复特效，
旧客户端仍保留原有兼容消息。粒子复用既有池，材质音效限制同时播放数量。

发射与回撞弹力带共用接触弹簧：法向压缩、切向形变和橡胶耗散连续计算，
球碰到弹力带后不会换成另一套储能。绕带的横向张力合力通过圆心，后缘滑移摩擦产生力矩，
保留斜拉控向；切向形变按碰撞后的实际位移更新，并随网络快照同步。

木质圆盘的碰撞恢复系数、满拉能量和桌面阻力一起校准。轻碰、斜碰与重碰依实际接触处理，
不追加撞击加速或随机旋转。120Hz 固定步长、4 次求解迭代、硬 CCD、本地预测和静止休眠保留。
这是针对木制桌面手感的接触近似，不是某个实物桌的实测材料模型；关键物理场景验证见
`tests/tabletop.test.mjs`，未做压力测试或宣称线上容量提升。

这轮单球关键场景的前后对比（速度使用游戏坐标单位，停止时间包含带回弹）：

| 场景 | 调整前 | 调整后 |
| --- | --- | --- |
| 中央满拉离带速度 | 43.50 | 27.94 |
| 中央满拉到停稳 | 4.76 秒 | 2.64 秒 |
| 初速 8、自旋 4 的自由滑行到停稳 | 1.43 秒 | 1.01 秒 |

同一压带位置的主动释放与被动回弹逐步一致；正碰动量、墙面回弹、带内碰撞总能量、
快照恢复、斜拉穿门和硬 CCD 已做少量场景验证。关闭预测接触后，离散碰撞可能出现
约一帧、0.13 单位的轻微压入再解开；未验证完整对局、设备端音频或性能容量。

## 材质音效

球碰球、撞木边、拿起和放下使用随客户端分发的 Kenney CC0 素材，详见
`client/audio/README.md` 和随附授权。9 个单声道 WAV 合计约 73KB，首次解锁音频后最多
2 个并行加载，解码结果常驻复用；碰撞时不发网络请求。弹力带释放使用本地生成的短阻尼弦声。
轻碰音量随速度衰减，声音最多 10 个同时播放，结束后断开音频节点；素材失败有本地回退。
碰撞火花与冲击圈收敛为少量短尘点，拖尾与弹力带余振也同步减弱。

## 小岛主题

首页结构在 `client/js/island-ui.mjs`，主题样式在 `client/css/island.css`，本地 SVG 插画与图标在
`client/assets/`。页面和对局采用奶油纸卡、草地与浅木桌配色，无外部字体或图片依赖。
首页、加载页和棋盘统一显示“广告位招租”；点击首页叶子可翻开 Chlx 的小纸条彩蛋。
`deploy/client-island.patch` 保存生成客户端中的主题入口与渲染调整，构建脚本会在物理补丁后自动应用；
修改 `game.mjs` 的主题部分时需同步该补丁，避免重建丢失。

对局默认开启“高清棋盘”：设备支持时按 2 倍像素绘制，总像素上限 500 万；设置中关闭后，
回到 250 万像素预算与手机 1.5 倍上限。阴影按画质和窗口尺寸在 1024～2048 间选择，
仍只在棋子或弹力带变化时更新；远景雾化移到棋盘之外，避免正常视角的材质泛白。

棋子顶部使用 512² 细木纹，所有棋子共享浅雕刻高度图；棋盘用定向木纹和浅凹凸表现木面，
倒角与清漆调整为清晰但柔和的边缘。保留原有网格分段、绘制对象和材质变体数量，
纹理只在建场时生成。按 RGBA8 含 mipmap 估算新增纹理显存约 9.5MiB，高清档还会增加
客户端像素填充和阴影开销；不增加服务器物理计算。已检查静态整盘/近景显示，未进行对局或性能测试。
